## ÉTAPE 10 — DEVIS `[EXISTE — trame et bibliothèque protégées]`
**A/B/C** Objectif : diagnostic → devis en < 10 min, **marge visible**, validation humaine. Acteurs : commercial ; dirigeant (remises). Experts : commercial, métreur, pricing, UX formulaires (progressive disclosure), CRO.
**D** Anomalies validées, catalogue (prix, coûts), surface/mesures, conditions du client.
**E/F/G** *Client* : reçoit un devis clair (prestations, photos pertinentes, options). *Commercial* : 3 gestes — structure proposée → ajuste → envoie. *Système* : mappe anomalie→prestation, calcule quantités depuis mesures, gèle les prix, calcule la marge estimée.
**H/I** Simple d'abord (prestation/quantité/prix), options avancées dépliables (remise, variantes, sections, conditions) ; wizard `[EXISTE]`. Mobile : devis simple ; complexe → PC.
**J/K/L** `estimate{version,statut,validité}`, `estimate_item{prestation, anomalie, qté, prix, coût}`. Automatisations : envoi → relances ; expiration → alerte. IA V2 : brouillon de structure (pas de prix inventé).
**M/N** Remise plafonnée par rôle + approbation dirigeant ; marge masquée hors droits. Notifications : demande d'approbation (À FAIRE).
**O/P/Q** Edge : catalogue modifié après envoi (prix figés), 2 personnes éditent (verrou), devis expiré, TVA différente. Sécurité : audit remise/prix.
**R/S** `estimate_created/sent/viewed/signed/expired`. KPI : délai diagnostic→devis, taux de signature, panier, marge estimée vs réelle.
**T/U/V** Friction : ressaisie, oubli de lignes. Risque : **Good/Better/Best** artificiel → seulement si plusieurs traitements réels.
**W** Acceptation : chaque ligne référence une anomalie ou est marquée « libre » ; prix figés à l'envoi ; PDF conforme à la trame.
**X/Y/Z** MVP `[EXISTE]`. V1 : marge, options cochables, lien de consultation. **Décision** : devis simple par défaut, complexité sur demande.
**RED TEAM** Commercial gonfle les remises → plafonds + audit. **SIMPLIFY** retirer sections/variantes du parcours par défaut. **SIMULATE** 10:25 structure proposée (3 lignes), 10:31 ajustée, marge 31 %, 10:32 envoi. **VALIDATE** 5 devis réels reproduits dans l'outil.

## ÉTAPE 11 — RELANCES
**A/B/C** Objectif : plus aucun devis oublié, sans harceler. Acteurs : commercial, système. Experts : sales, lifecycle marketing, UX notifications, privacy.
**D** Date d'envoi, ouverture/consultation, montant, historique, dernière relance, réponse.
**E/F/G** *Client* : reçoit des relances **différentes, utiles** (pas 7 fois « avez-vous vu ? »), s'arrête dès qu'il répond. *Commercial* : voit 1 action proposée + brouillon. *Système* : séquence J+2 (consultation ?) → J+5 appel → J+10 valeur ajoutée (variante/option/question) → J+21 échéance/expiration ; plafond 4 ; horaires respectés.
**H/I** Action Center « Relances » ; mobile : appeler / envoyer en 1 tap.
**J/K/L** `follow_up{devis, canal, statut, brouillon}`. Automatisations : `estimate_sent` → programmation ; `estimate_viewed` → avance/ajuste ; `client_replied` → stop. IA V2 : brouillon contextualisé.
**M/N** Commercial du dossier ; manager voit les non-relancés. Notifications : relance due (À FAIRE), devis chaud consulté 3× (URGENT).
**O/P/Q** Edge : client demande de ne plus être contacté (opt-out), devis signé entre-temps, montant faible (séquence allégée). Erreurs : SMS échoué → e-mail. Sécurité : désabonnement respecté.
**R/S** `follow_up_sent/replied`, KPI : % devis relancés, taux de réponse, délai réponse→signature.
**T/U/V** Friction : relance à la mémoire. Risque : harcèlement → plafond + opt-out + ton.
**W** Acceptation : tout devis > seuil a une relance planifiée ; aucun envoi après réponse/opt-out ; brouillon validé avant envoi.
**X/Y/Z** MVP : tâches de relance programmées + modèles. V1 : suivi de consultation + séquences. **Décision** : le système **propose**, le commercial **envoie**.
**RED TEAM** Relances automatiques envoyées à un client déjà signé → arrêt sur événement. **SIMPLIFY** 3 relances + 1 clôture. **SIMULATE** J+2 : « devis ouvert 2× » → SMS proposé « une question sur l'option gouttière ? ». **VALIDATE** taux de réponse sur 30 devis.

## ÉTAPE 12 — SIGNATURE / ACOMPTE
**A/B/C** Objectif : signature simple et valable, acompte encaissé vite. Acteurs : client, commercial, admin. Experts : juridique (à valider), paiement, UX client 65+.
**D** Devis validé, conditions.
**E/F/G** *Client* : ouvre le lien → lit → **Accepter et signer** (code SMS) → propose de régler l'acompte → reçoit le récapitulatif. *Commercial* : reçoit « signé ». *Système* : preuve horodatée, hash du PDF, facture d'acompte auto `[EXISTE]`, lien de paiement, création du chantier `[EXISTE]`.
**H/I** Page publique mobile-first sans compte ; PC pour suivre.
**J/K/L** `signature{ip, horodatage, méthode, hash}`, `invoice(acompte)`. Automatisations : `estimate_signed` → chantier + acompte + tâche approvisionnement + remerciement. IA : PAS D'IA NÉCESSAIRE.
**M/N/O** Permissions : lecture publique par jeton ; modification post-signature interdite (avenant). Edge : signature partielle, client veut modifier (nouvelle version), acompte refusé (relance), signature en présentiel (tablette). **P/Q** Erreurs : code SMS non reçu → e-mail. Sécurité : jeton long, expiration, journal.
**R/S** `estimate_signed`, `deposit_paid`. KPI : délai envoi→signature, % acompte payé < 48 h.
**T/U/V** Friction : impression/scan → supprimée. Risque juridique → valeur probante à valider.
**W** Acceptation : devis signé non modifiable ; chantier créé automatiquement ; preuve téléchargeable.
**X/Y/Z** MVP : bouton « Gagné » manuel `[EXISTE]`. V1 : signature électronique + paiement en ligne. **Décision** : prestataire de signature, pas de solution maison.
**RED TEAM** Client conteste → pack de preuves. **SIMPLIFY** signature simple (pas de compte). **SIMULATE** J+3 14:02 signature, 14:03 acompte 30 %, 14:03 chantier créé. **VALIDATE** avis juridique sur le niveau de signature.

## ÉTAPE 14 — PRÉPARATION DU CHANTIER (pre-job check)
**A/B/C** Objectif : arriver sur le chantier avec tout. Acteurs : conducteur/bureau. Experts : achats/matériaux, chef d'équipe.
**D** Tâches, matériaux (bibliothèque `[EXISTE]`), contraintes (accès, échafaudage), documents.
**E/F/G** *Client* : reçoit date, durée, ce qu'il doit prévoir (accès, stationnement). *Bureau* : checklist « ce qui manque » (acompte ? matériaux ? autorisation ? équipe compétente ? durée ? équipement ?). *Système* : génère la liste de matériel du devis, propose les fournisseurs, alerte les manques.
**H/I** PC : checklist de prérequis ; mobile chef d'équipe : liste matériel `[EXISTE]`.
**J/K/L** `job_material`, `purchase`, `precheck`. Automatisations : chantier planifié → commande proposée ; matériel non reçu J-2 → alerte. IA V2 : quantités depuis mesures (proposées).
**M/N/O** Permissions : achats/conducteur. Edge : livraison retardée, matériel spécial, permis. **P/Q** Erreurs : fournisseur indisponible → alternative. **R/S** KPI : % chantiers « prêts » à J-2. **W** Acceptation : impossible de passer « planifié » sans prérequis critiques (dérogation tracée). **X/Y/Z** MVP : checklist matériel + prérequis. V2 : commande fournisseur. **RED/SIMPLIFY** : 6 prérequis maximum ; **SIMULATE** J-2 : « matériel Dupont non reçu » → appel fournisseur ; **VALIDATE** liste réelle des prérequis avec un conducteur.

## ÉTAPE 15 — PLANIFICATION DES ÉQUIPES
**A/B/C** Objectif : équipe compétente, au bon endroit, avec décision humaine. Acteurs : dirigeant/conducteur ; système propose. Experts : responsable planning, chef d'équipe, météo, routage.
**D** Durée (somme des postes ÷ productivité), compétences, disponibilités, localisation, matériel, dépendances, météo.
**E/F/G** *Client* : reçoit dates confirmées et rappels. *Planificateur* : voit une proposition avec justification, valide/ajuste. *Système* : score simple (compétence, proximité, charge, dépendances), alertes de conflit et de météo.
**H/I** PC : vues jour/semaine/équipe/chantier + carte ; mobile : équipe voit ses jours.
**J/K/L** `job_assignment`, `crew`. Automatisations : chantier planifié → notifs + réservation matériel. IA : PAS D'IA NÉCESSAIRE au MVP.
**M/N/O** Permissions : planificateur écrit ; poseur lit. Edge : absence, chantier qui déborde, urgence insérée, pluie (report proposé). **P/Q** Erreurs : conflit détecté → refus avec explication. **R/S** KPI : taux d'occupation, retards, km. **W** Acceptation : aucun chevauchement de ressource sans dérogation. **X/Y/Z** MVP : planning manuel + conflits ; V1 : propositions ; V2 : carte/tournées. **RED/SIMPLIFY** : pas de solveur ; **SIMULATE** semaine 40 : 3 chantiers, 1 report météo proposé ; **VALIDATE** avec un planificateur réel.
